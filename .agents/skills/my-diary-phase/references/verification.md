# 作業後検証

## 選択原則

すべてのPhaseで全項目を無条件に実行しない。変更内容、リスク、個別プロンプトに応じて必要な項目を選び、実行結果、対象外、未実施理由を分けて記録する。検証できない項目を成功扱いしない。

## 静的検証と変更範囲

- `git diff --check`で空白エラーを確認する。
- `git status --short`、`git diff --stat`、`git diff`で変更ファイルと内容を確認する。
- 変更ファイルが個別プロンプトのPhase範囲内か確認する。
- stage済み差分がある場合は`git diff --cached`も確認する。
- プロジェクトの実際のscriptを確認して、変更に応じてlint、typecheck、production buildを実行する。
- コマンド、終了コード、警告、失敗内容を記録する。既存問題と今回の回帰を区別する。

## pgTAP、migration、linked schema

- DB、認証、RLS、visibilityに関係する変更では、既存手順に従って対象pgTAPと必要な回帰テストを実行する。
- migration履歴と差分を確認し、既存migrationが変更されていないことを確認する。
- linked schema diffは、個別プロンプトがリモートの読み取り専用確認を許可し、既存認証で安全に実行できる場合だけ行う。
- DB変更なしのPhaseでは、不要なmigration作成・適用・repairを行わない。
- 認証、RLS、visibility等の権限制御は、UI表示だけでなくDB側の最終認可まで確認する。クライアント由来のユーザーIDを認可根拠にしていないことを確認する。

## 秘密情報

- 差分と変更ファイルにAPIキー、パスワード、トークン、接続文字列、Service Role、テストユーザー情報が含まれていないことを確認する。
- 秘密らしき値を発見しても報告へ転載しない。ファイルと種別だけを安全に示し、作業を止める。
- `git ls-files --error-unmatch .env.local`等の内容を表示しない方法で、`.env.local`が追跡されていないことを確認する。
- 未追跡・stage済みファイルも確認し、秘密情報をcommit対象へ含めない。

## UI変更時のブラウザ検証

UI変更がある場合だけ、個別プロンプトで指定された対象画面と操作を検証する。

### 画面幅

- 320px
- 360px
- 375px
- 390px
- 1280px

各幅で`scrollWidth <= clientWidth`を確認し、意図しない横スクロールがないことを確認する。長文、改行、連続半角文字列でもレイアウトを確認する。

### 操作と状態

- labelと入力要素の関連付け
- visibleなフォーカスリングとキーボード操作
- `disabled`と`aria-disabled`の意味に合った使用
- エラー時の`aria-invalid`、`aria-describedby`、`role="alert"`
- 保存中表示と二重送信防止
- 成功、失敗、再試行、境界値
- 認証状態と権限別の表示・操作

### console

console warning/error、network failure、hydration errorを確認する。既存警告と今回の変更による警告を区別する。

自動ブラウザで再現できない認証、OSダイアログ、ファイル選択、端末固有操作等は「未実施・手動確認」として、対象画面、手順、期待結果を報告する。

## 検証不能項目の報告

次を明記する。

1. 検証できなかった項目
2. 理由
3. 実行を試みた範囲
4. 代替確認の有無
5. 残るリスク
6. 手動確認手順または次の安全な作業
